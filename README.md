# CASE BATTLE

Симулятор кейсов CS2: 146 кейсов и 16 527 вариантов предметов из каталога исходной игры. Сервер хранит аккаунты, баланс, инвентарь, историю и настройки в Cloudflare D1. Монеты виртуальные.

## Запуск

Нужен Node.js 22.13 или новее. При новой установке:

```powershell
npm run install:ci
npm run build
node node_modules/wrangler/bin/wrangler.js d1 execute site-creator-d1 --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_bored_reavers.sql
node node_modules/wrangler/bin/wrangler.js d1 execute site-creator-d1 --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0001_user_avatars.sql
```

Сайт: http://127.0.0.1:5173/, администрация: http://127.0.0.1:5173/admin.

Создайте локальную `.dev.vars` с `ADMIN_LOGIN` и `ADMIN_HASH`, затем запустите установленный проект:

```powershell
Copy-Item .dev.vars dist/server/.dev.vars
npm start -- --port 5173
```

Миграции применяются один раз при создании базы; существующую базу не пересоздавайте. Конфигурация bindings находится в `vite.config.ts`. Локальные данные лежат в игнорируемой папке `.wrangler/state`. После изменения кода выполните `npm run build` и скопируйте `.dev.vars` в новую сборку повторно.

В профиле можно загрузить PNG, JPEG или WebP до 10 МБ. Изображение уменьшается до 192×192, сохраняется в D1 и отображается в профиле и шапке.

## Доступ администратора

Логин задаётся переменной `ADMIN_LOGIN`, пароль — хешем `ADMIN_HASH` формата `salt:hash`, PBKDF2-SHA256, 100000 итераций. Локальная `.dev.vars` и секреты размещения не входят в Git. Открытый пароль не хранится в исходниках.

Администратор управляет балансами (прибавить, вычесть, установить), выдаёт предметы, блокирует аккаунты, редактирует кейсы и цены, задаёт веса выпадения, управляет промокодами, экономикой, объявлением и обслуживанием, отвечает на обращения. Изменения записываются в журнал.

## Язык

RU / EN в шапке и настройках переключает игровой интерфейс, админку и названия всех 16 527 вариантов скинов. Выбор сохраняется в браузере.

## Игровые разделы

- Кейсы: 1–10 открытий, рулетка, быстрое открытие, продажа результатов, состав и текущие вероятности.
- Апгрейд: до 6 предметов, дополнительные монеты, множители и выбор цели из полного каталога.
- Контракт: обмен 3–10 предметов с анимацией результата и регулируемым диапазоном стоимости.
- Инвентарь: продажа, выбор предметов и быстрый переход в контракт или апгрейд.
- Фармилка, ежедневный бонус, одноразовые промокоды, профиль, история, рейтинг и поддержка. Дополнительные разделы доступны через настройки.
- Левая лента случайных топовых скинов обновляется каждые 2,1 секунды.
- Счётчик онлайна показывает 5000 плюс число игроков, активных за последние 45 секунд. Видимая вкладка отправляет heartbeat каждые 10 секунд; вкладки одного аккаунта учитываются один раз. Оплата и ввод данных карты отсутствуют.

## Проверка

`node node_modules/typescript/bin/tsc --noEmit` проверяет типы. `npm run build` собирает Worker и клиент. Локальная интеграционная проверка `scripts/verify-api.mjs` проверяет 18 сценариев и принимает пароль администратора через скрытый stdin. Отчёт: `work/api-verification.json`.

Состояние игрока обновляется с проверкой версии записи: параллельные продажи не начисляют монеты повторно. Пароли хешируются, сессии используют HttpOnly cookies, изменяющие запросы проверяют Origin, вход и действия ограничиваются по частоте.

## Соответствие примеру

Включены все 16 527 исходных вариантов предметов, 146 кейсов, активные составы и цены. Все кейсы и 16 491 вариант предметов используют спрайты, извлечённые непосредственно из игры. Для 36 вариантов девяти рисунков сохраняются соответствующие CS-изображения; список исключений находится в `reference/artwork-audit.json`.

В интерфейсе используются оригинальные изображения и пять извлечённых звуков. Анимации воссозданы по наблюдениям. Точное покадровое совпадение и исходные вероятности выпадения не подтверждены. Подробности и происхождение файлов — в `SOURCES.md`.

## Размещение

Игра: https://case-battel-5-83-140-108.sslip.io/ — админка: `/admin`. Исходники игры и админки находятся в этом репозитории.

Основное размещение — Ubuntu VDS, Node.js 24, SQLite и Caddy с HTTPS. Сборка `npm run build:vds` использует те же React-компоненты, каталог, стили, анимации и API, что и версия Sites. Данные лежат отдельно от сборки в `/var/lib/case-battel/game.sqlite`.

Таймер `case-battel-update.timer` проверяет GitHub `main` каждые две минуты. При новом коммите отдельный пользователь `case-deploy` устанавливает зависимости, проверяет типы, собирает игру и админку и активирует релиз. Неудачный запуск возвращает предыдущий релиз; база игроков сохраняется отдельно от исходников.

Шаблон GitHub Actions лежит в `deploy/vds/github-actions.yml`. Он не активирован: текущее подключение GitHub не разрешает запись workflow. Для работы сайта и автоматического обновления этот шаблон не требуется.

Конфигурация сервера находится в `deploy/vds`. Пароль администратора задаётся хешем в `/etc/case-battel/runtime.env`, а не в Git. Служба `case-battel` запускается автоматически после перезагрузки. Ежедневные копии базы сохраняются в `/var/backups/case-battel`, хранятся последние 14 копий; перед публикацией также создаётся копия.

Версия Sites использует Vinext, Cloudflare Workers и D1; её идентификатор сохранён в `.openai/hosting.json`. GitHub Pages служит входной ссылкой на полный серверный сайт.
